# HWPX 생성 파이프라인 계약

이 문서는 Markdown 수업안 작성자, HWPX 생성 담당자, 검증 담당자의 역할과 인수 기준을 정한다. 이 저장소에는 Markdown만 보관하며 HWPX는 생성·검증 담당자의 별도 작업 위치에서 다룬다.

## 1. 인수물 흐름

`원문보존 Markdown` → `피드백 반영 기록` → `확정 수업안 Markdown` → `HWPX 생성 요청 Markdown` → **별도 작업 위치에서 HWPX 생성** → **별도 작업 위치에서 역추출 검증** → `검증 보고서 Markdown`

## 2. 작성자 인수 기준

생성 요청 전 수업안은 다음을 모두 충족해야 한다.

- 문서 상태가 `확정`이다.
- 기준 원문 경로와 원문 쪽·문장이 기록돼 있다.
- 원문 사실·재구성 제안·교사 확인 필요가 구분돼 있으며, 제안과 미확정 항목이 없다.
- 한 주제의 수업지도안은 기본적으로 **6차시 TRACES**이며, 총 차시와 차시별 계획·예상 산출물의 행 수가 일치한다.
- 차시 흐름에 따라 학생의 중간 산출물과 최종 성과물이 연결된다. 최종 산출물만 제시하거나 여러 차시를 하나의 산출물 행으로 합치지 않는다.
- CBL Challenge는 교사가 답·방법·산출물을 미리 지정한 과제가 아니라, 학생이 자료·조건·이해관계자 관점을 검토해 해결 방향을 선택·정당화할 수 있는 질문으로 제시된다.
- Act가 발표만으로 끝나지 않고, 학생이 자신 또는 주변의 실제·안전한 사용 맥락에서 수학적 근거로 선택한 해결안을 적용·시험하며, 피드백에 따라 수정하거나 미수정 이유와 한계를 기록한다.
- 실제 적용은 기본값이다. 안전·개인정보·수업 운영·승인·시간 조건을 충족하면 실제·저위험 맥락에서 적용·시험한다. 이 조건을 충족하지 못하거나 원문이 실제 관찰·개입을 금지할 때만 교사가 설계한 모의 적용으로 전환하며, 실제 변화나 실제 수요자 반응으로 과장하지 않고 적용 범위·한계를 기록한다.
- 매 차시에 A0~A4 또는 `해당 없음` 사유가 있다.
- 안전·개인정보·보안 경계가 원문 근거와 함께 명시돼 있다.
- 교사명, 학교급·학년, 과목, 단원, 성취기준, 수업 시간, 평가 기준이 확정돼 있다.

## 3. 생성 담당자 인수 기준

생성 담당자는 `templates/HWPX-생성-요청서.md`와 확정 수업안을 함께 받는다.

- 승인된 HWPX 양식과 생성 도구만 사용한다.
- 양식의 ZIP/XML을 문자열 치환으로 직접 편집하지 않는다.
- 표의 열 순서·병합·수식 영역을 임의로 바꾸지 않는다.
- 총 차시에 맞는 모든 차시를 생성한다.
- 생성 후 HWPX 파일명·생성 도구·양식 버전·생성 시각·SHA-256을 검증 담당자에게 전달한다.

## 4. 검증 담당자 인수 기준

검증 담당자는 생성된 HWPX를 열어 보고, ZIP 무결성 검사와 Markdown 역추출을 수행한다.

- ZIP 무결성, HWPX 열기, section/쪽 수를 확인한다.
- 역추출본에서 제목·교사·학년·과목·단원·성취기준·총 차시를 대조한다.
- 각 차시의 목표·활동·A0~A4·예상 산출물·평가 증거가 빠지지 않았는지 대조한다.
- 안전·개인정보·보안 경계, 수식, 표, 출처를 대조한다.
- 결과를 `templates/HWPX-검증-보고서.md` 형식으로 이 저장소에 기록한다.

## 5. 실패 처리

다음 중 하나라도 있으면 배포 보류다.

- HWPX가 열리지 않거나 ZIP 무결성에 실패함
- 역추출 Markdown과 확정 수업안의 내용 또는 차시 수가 다름
- 수식·표·출처·안전 경계가 누락됨
- 원문 근거 없는 제안 또는 `교사 확인 필요` 항목이 HWPX에 포함됨
- 검증 보고서가 없음
