# 수업안 재구성 작업장

이 저장소는 **Markdown 원문·검토 기록·확정 수업안만 보관**한다. 생성된 HWPX, 중간 산출물, 실행 스크립트, 템플릿 바이너리는 저장하지 않는다.

## 역할 분리

| 역할 | 이 저장소에서 하는 일 | 저장소 밖에서 하는 일 |
|---|---|---|
| 콘텐츠 작성자 | 원문 근거를 확인하고 확정 Markdown을 작성한다. | HWPX 생성 요청에 필요한 입력을 준비한다. |
| 검토자 | 원문 사실·재구성 제안·교사 확인을 구분하고 승인 여부를 기록한다. | 생성본의 역추출 결과를 대조한다. |
| HWPX 생성 담당자 | 확정 Markdown과 생성 명세를 읽는다. | 승인된 양식·생성 도구로 HWPX를 생성한다. |
| HWPX 검증 담당자 | 검증 보고서의 근거를 이 저장소에 Markdown으로 남긴다. | ZIP 무결성, HWPX 역추출, 표·수식·쪽 구성 대조를 실행한다. |

## 저장 구조

- `원문보존/`: HWPX에서 추출한 원문 Markdown. 읽기 전용이다.
- `피드백-반영-기록지.md`: 원문 근거와 재구성 판단을 기록한다.
- `한글파일-변환-템플릿.md`: 확정 Markdown이 갖춰야 할 수업안 구조다.
- `동아리-CBL-수업-프레임워크.md`: 동아리 공통의 TRACES 6차시 CBL 활동 프레임워크와 Act·평가 기준을 제시한다.
- `교사용-CBL-수업안-개선-안내문.md`: 기존 초안에서 자주 나타난 보완 지점과 재구성 기준을 교사에게 안내한다.
- `PIPELINE.md`: 생성·검증 담당자가 따라야 하는 HWPX 생성 파이프라인 계약이다.
- `templates/`: 확정 수업안과 생성 요청·검증 보고서를 작성하는 Markdown 양식이다.

## 저장 규칙

1. 이 저장소에는 `.md` 파일만 둔다.
2. HWPX는 생성 담당자의 별도 작업 위치에만 만든다.
3. HWPX를 다시 추출한 검증 결과는 `검증-보고서.md` 형식의 Markdown으로만 이 저장소에 반영한다.
4. `교사 확인 필요` 또는 `재구성 제안`이 남은 Markdown은 HWPX 생성 입력으로 넘기지 않는다.
5. 원문보존본은 원본 표현·빈 차시·중복 표기·이미지 자리표시를 유지한다.
