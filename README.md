# MAIL CBL 최종 제출: 6차시 수업지도안 제작 안내

이 저장소는 MAIL 동아리 구성원이 **교사별로 CBL 수업 주제 하나를 선택해 TRACES 6차시 수업지도안을 완성하고, 최종 HWPX 산출물 제작까지 연결하는 공동 작업 공간**입니다.

우리가 제출하는 것은 아이디어 목록이나 일부 차시 초안이 아닙니다. 한 주제에 대해 문제를 정하고, 수학적으로 탐구하고, 해결안을 안전하게 시험하며, 결과를 해석하고 수정하는 **완결된 6차시 수업지도안**입니다. Markdown 원문, 검토 기록, 확정 수업안, HWPX 생성·검증 기록을 이 저장소에서 함께 관리합니다.

## 이번 작업의 목표

각 교사는 다음을 하나의 흐름으로 완성합니다.

1. 기존 피드백을 반영해 수업안의 빈 차시·약한 연결·불분명한 산출물을 보완합니다.
2. 선택한 수업 주제 하나에 TRACES 전략을 적용합니다.
3. 그 주제로 기본 6차시 CBL 수업지도안을 작성합니다.
4. 확정 Markdown을 바탕으로 교사용 수업지도안, 학생 활동지, 평가 기록지 등 필요한 산출물의 제작 요청을 준비합니다.
5. 승인된 양식과 생성 절차로 HWPX를 만들고, 역추출 검증까지 마친 뒤 최종 제작을 종료합니다.

## 왜 TRACES 6차시인가

CBL은 조사 후 발표하는 활동이 아니라, 학생이 수학적 근거로 선택한 해결안을 실제 또는 안전한 맥락에서 적용·시험하고 결과를 해석해 수정하는 학습입니다. 이를 짧은 동아리 활동 안에서도 빠뜨리지 않기 위해 여섯 단계를 고정합니다.

| 차시 | TRACES 단계 | 학생이 남길 핵심 증거 |
|---:|---|---|
| 1차시 | **T - Trigger / 문제 포착·도전 정식화** | Big Idea, Essential Question, 문제 정의문, Challenge |
| 2차시 | **R - Research / 질문 기반 탐구** | 질문, 자료·변수·조건표, 자료 한계 |
| 3차시 | **A - Architect / 수학적 해결안 설계** | 식·표·그래프, 가정, 해결안 후보와 선택 근거 |
| 4차시 | **C - Change-plan / 실행 계획** | 대상·맥락, 실행물, 판단 기준, 안전·중단 조건, 대체안 |
| 5차시 | **E - Execute / 제한 실행** | 실행물 또는 모의 실행물, 관찰값·피드백, 변경 기록 |
| 6차시 | **S - Study / 실행 증거 해석·수정·성찰** | 수정 전후 비교, 한계, 최종 제안, 개인 성찰 |

- Act는 발표 자체가 아닙니다. 해결안을 실제·안전한 맥락에서 사용하거나 제한적으로 시험하고, 관찰·판단 기준과 수정 근거를 남기는 행동입니다.
- 안전, 개인정보, 수업 운영 또는 시간 조건 때문에 실제 적용이 적절하지 않으면 **명시적 모의 적용**으로 전환할 수 있습니다. 이때 실제 효과나 실제 대상자 반응으로 과장하지 않고 적용 범위와 한계를 기록합니다.
- 동아리 기본형은 6차시입니다. 5차시 압축형은 실행 계획과 제한 실행을 같은 차시에 수행할 수 있을 때만 예외로 사용합니다.

자세한 기준은 [`동아리-CBL-수업-프레임워크.md`](동아리-CBL-수업-프레임워크.md), 기존 초안을 고칠 때는 [`교사용-CBL-수업안-개선-안내문.md`](교사용-CBL-수업안-개선-안내문.md)을 먼저 읽습니다.

## 동아리 구성원 작업 순서

### 1. 주제 하나를 고르고 피드백을 반영합니다

- 교사별로 **수업 주제 하나만** 선택합니다. 여러 주제를 얕게 나누지 않습니다.
- 원문 또는 기존 초안은 [`원문보존/`](원문보존/)에서 확인합니다. 이 폴더는 읽기 전용입니다.
- [`피드백-반영-기록지.md`](피드백-반영-기록지.md)에 무엇을 유지·수정·확인할지 기록합니다.
- 원문 사실, 재구성 제안, 교사 확인이 필요한 내용을 섞지 않습니다. 미확정 내용은 최종 HWPX 입력으로 넘기지 않습니다.

### 2. TRACES에 맞춰 6차시 수업지도안을 작성합니다

[`templates/확정-수업안-템플릿.md`](templates/확정-수업안-템플릿.md)을 복사해 교사별 작업 폴더에 새 Markdown 파일을 만듭니다. 파일명은 `교사명_과목_수업주제_TRACES6차시.md`처럼 누가 보아도 알 수 있게 씁니다.

수업안에는 반드시 다음이 있어야 합니다.

- 성취기준, Big Idea, Essential Question, 학생이 선택·정당화할 수 있는 Challenge
- 1~6차시 각각의 목표, 학생 활동, 교사 지원, 예상 산출물, 평가·관찰 증거
- 수학적 모델의 변수·단위·가정·검산과 해결안 선택의 근거
- Act의 대상·맥락·실행물·판단 기준·안전·중단 조건·대체안
- 모둠 산출물과 별개인 개인 설명·역할 기록·성찰 중 하나 이상의 개인 증거
- AI를 사용한다면 목적, 입력 경계, 학생의 직접 판단, 검증, 기록; 사용하지 않으면 `AI 미사용`

작성 중 자주 생기는 문제와 개선 방향은 [`교사용-CBL-수업안-개선-안내문.md`](교사용-CBL-수업안-개선-안내문.md)에 정리되어 있습니다.

### 3. 예상 산출물을 먼저 설계합니다

6차시의 산출물은 마지막 발표 하나가 아닙니다. 앞 차시의 증거가 다음 차시의 판단 재료가 되도록 연결합니다.

| 단계 | 권장 산출물 틀 | 제작 방법 예시 |
|---|---|---|
| T, R | 문제 정의문, 질문·자료·변수·조건표, 조사 기준표 | Markdown 표 또는 활동지 초안 |
| A | 식·표·그래프, 해결안 후보 비교표, 선택 근거 | 학생 계산·그래프를 바탕으로 표와 설명 작성 |
| C, E | 실행 계획서, 안내물·선택 기준표·시제품, 관찰·피드백 기록 | 바이브코딩으로 시제품 또는 웹 안내물 초안 제작 후 교사가 내용·안전·수학 근거 검토 |
| S | 수정 전후 비교표, 최종 제안서, 개인 성찰 | 실행 기록과 피드백을 근거로 최종 문서화 |

디지털 시각 자료가 필요하면 다음 순서로 만듭니다.

1. 먼저 수업안에 목적, 대상, 핵심 수학 내용, 학생 조작·판단, 안전·개인정보 경계를 적습니다.
2. 바이브코딩 또는 HTML로 **초안**을 만듭니다. 생성 결과를 사실·수학·저작권 측면에서 사람이 검토합니다.
3. 검토한 HTML을 PDF 또는 이미지로 변환합니다.
4. HWPX 생성 담당자가 승인된 양식 안의 필요한 위치에 PDF·이미지를 삽입합니다.
5. 검증 담당자가 HWPX에서 표·수식·이미지·쪽 구성을 열람하고 역추출본과 확정 Markdown을 대조합니다.

AI·바이브코딩은 제작 보조 수단입니다. 학생 또는 교직원의 식별 정보, 비공개 학교 정보, 검증하지 않은 수치·출처를 입력하거나 그대로 사용하지 않습니다.

### 4. 확정 후 HWPX 제작을 요청합니다

- 수업안의 상태가 `확정`이고 빈 대괄호, `교사 확인 필요`, 미확정 재구성 제안이 없을 때만 HWPX 생성을 요청합니다.
- [`templates/HWPX-생성-요청서.md`](templates/HWPX-생성-요청서.md)에 확정 수업안 경로, 생성 대상, 파일명, 승인 양식, 생성 도구, 담당자와 작업 위치를 기록합니다.
- 생성 담당자는 승인된 양식과 도구로만 HWPX를 생성합니다. 이 저장소에는 HWPX, 이미지 원본, HTML, PDF, 실행 스크립트를 넣지 않습니다.
- 검증 담당자는 [`templates/HWPX-검증-보고서.md`](templates/HWPX-검증-보고서.md)를 작성해 ZIP 무결성, 역추출, 표·수식·이미지·쪽 구성 대조 결과를 남깁니다.

전체 인수 기준과 실패 처리 기준은 [`PIPELINE.md`](PIPELINE.md)에 있습니다.

## 저장소 규칙

- 이 저장소에는 Markdown 원문, 검토 기록, 확정 수업안, 생성 요청서, 검증 보고서만 보관합니다.
- `원문보존/`의 원본 표현, 빈 차시, 중복 표기, 이미지 자리표시는 수정하지 않습니다.
- HWPX와 중간 산출물(HTML, PDF, 이미지 원본, 실행 스크립트, 바이너리 템플릿)은 생성 담당자의 별도 작업 위치에만 보관합니다.
- HWPX 검증 결과는 바이너리 대신 Markdown 검증 보고서로 남깁니다.
- 원문 근거가 없는 내용, 교사 확인이 끝나지 않은 제안, 개인정보·보안 경계를 벗어난 자료는 최종 수업안과 HWPX에 넣지 않습니다.
