# 교사별 원문 피드백 파일

이 폴더에는 **교사별 독립 Markdown**을 둔다. 각 파일은 원문보존본을 직접 대조한 제출자료 설계·TRACES 반영 기록이며, 확정 수업안이나 HWPX 입력본이 아니다.

## 이 폴더의 사용 순서

공통 개념이 낯설면 먼저 [`public/CBL-TRACES-교사용-빠른-길잡이.md`](../../public/CBL-TRACES-교사용-빠른-길잡이.md)를 읽는다. 기존 원문 대신 새 주제를 만들 때는 [`public/새-주제-CBL-TRACES-설계-프롬프트-모음.md`](../../public/새-주제-CBL-TRACES-설계-프롬프트-모음.md)을 사용한다.

1. 교사는 자신의 파일에서 기준 원문·성취기준·안전 경계가 맞는지 먼저 확인한다.
2. `원문 근거 → 피드백 → 권고 6차시 → 활동지·예시·평가 자료 명세 → 확정 질문` 순으로 검토한다.
3. `[권고안]`을 수용·수정·보류로 표시하고, 승인한 내용만 `02-TRACES-수업안-확정/확정-수업안-템플릿.md`에 옮긴다.
4. 확정 수업안 뒤에 학생용 HTML 활동지, 교사용 예시, PDF·PNG, HWPX `content.py`를 만든다.
5. HWPX는 템플릿 기반으로 생성하고, 한글 프로그램 수작업 삽입·조판과 ZIP·역추출·페이지 검증을 거친다.

## 공통 제출 경계

- 학생용 활동지에는 정답·교사용 계산 과정을 넣지 않는다.
- 교사용 예시는 공통 모델의 수치·단위·식·그래프·역방향/변경 시나리오를 교사가 검산한 뒤에만 만든다.
- 발표·공유는 E(제한 실행)를 대신하지 않는다. E에는 계획한 기준 아래 해결안을 안전하게 적용·시험한 기록이 있어야 한다.
- 실제 변화·외부 반응·승인 여부를 평가하지 않는다. 수학적 근거, 제약 분석, 시험 증거 해석, 수정 이유와 개인 증거를 평가한다.
- HWPX 생성 전에는 확정 Markdown이 단일 내용 기준이다. 생성 뒤에는 실제 열기, `unzip -t`, Kordoc 역추출, PDF/페이지 렌더링, 한글 수작업 검수를 모두 한다.
