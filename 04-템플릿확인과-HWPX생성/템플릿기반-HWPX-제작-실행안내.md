# 템플릿 기반 HWPX 제작 실행 안내

> 이 문서는 이전 `club-plan`에서 실제 작동을 재현한 `form_template.hwpx + build_engine.py + content.py` 방식을, 이번 TRACES 6차시 최종 제출에 적용하는 순서를 정한다.
>
> 핵심: 확정 Markdown에서 활동지·교사용 예시의 내용과 삽입 위치까지 먼저 승인한다. 그 뒤 템플릿 복사본으로 **수업안 뼈대 1차시 시험 생성**을 해 양식 호환성을 확인하고, HTML→PDF·PNG 부속자료를 만든다. 마지막에 부속자료를 포함한 전체 차시 HWPX를 생성·삽입하고, 반드시 사람이 한글 프로그램에서 조판·삽입·최종 검수를 한다.

## 실제 재현 확인 결과

이전 `club-plan`의 보존 커밋 `3e088cdf`에서 다음 조합을 복원해 실행했다.

```text
form_template.hwpx
build_engine.py
교사별 content.py
```

김규봉의 과거 1~2차시 `content.py`로 통합 HWPX를 실제 생성했고 다음을 확인했다.

- 생성 엔진이 차시별 HWPX 2개와 `1-2차시_통합.hwpx`를 생성함
- `unzip -t` ZIP 무결성 통과
- 통합 문서에 `Contents/section0.xml`, `Contents/section1.xml`이 존재함
- Kordoc 역추출 성공, 제목·성취기준·1·2차시 수업 내용·차시별 산출물 문구가 모두 확인됨

따라서 이 방식은 출발점으로 사용할 수 있다. 다만 과거 `content.py`는 2차시 구조이므로, 이번 제출에서는 확정된 TRACES 6차시 내용을 `CHASI[1]`~`CHASI[6]`으로 새로 작성해야 한다.

## 전체 제작 순서

| 순서 | 담당 | 만드는 것 | 자동화 범위 | 사람 수작업·검수 |
|---:|---|---|---|---|
| 1 | 콘텐츠 작성자 | 확정 수업안 Markdown과 부속자료 승인 목록 | 작성 보조 가능 | 교육과정·수학·Act·안전·평가·활동지 삽입 위치 확정 |
| 2 | 생성 담당자 | `content.py`와 템플릿 복사본 | 기존 구조를 바탕으로 작성 보조 가능 | Markdown과 한 항목씩 대조 |
| 3 | 생성 담당자 | **1차시 뼈대 시험 HWPX** | `build_engine.py` | 한글에서 표·글꼴·수식·차시 위치가 템플릿대로인지 확인 |
| 4 | 활동지 제작자 | 학생 활동지·교사용 예시 HTML | 바이브코딩 보조 가능 | 수학·출처·개인정보·저작권·인쇄 품질 확인 |
| 5 | 활동지 제작자 | PDF·PNG | 브라우저/Chrome 변환 가능 | PDF를 열어 표·수식·빈칸·흑백 인쇄 확인 |
| 6 | 생성 담당자·편집 담당자 | 6차시 통합 HWPX와 부속자료 삽입본 | `build_engine.py` 후 일부 보조 가능 | 한글에서 PDF·PNG 삽입, 크기·위치·쪽 나눔 조정 |
| 7 | 검증 담당자 | 검증 보고서 | ZIP·역추출 보조 가능 | 실제 페이지 열람, 표·수식·이미지·쪽 구성 최종 판정 |

자동 생성은 **초안 제작을 빠르게 하는 단계**다. 최종 제출용 HWPX의 조판과 자료 삽입까지 자동으로 완성됐다고 간주하지 않는다.

## 1. 먼저 확정 Markdown을 만든다

다음이 모두 확정된 뒤에만 `content.py`를 작성한다.

- 교사, 학년, 과목, 단원, 성취기준, 수업 시간
- Big Idea, Essential Question, Challenge
- TRACES 1~6차시의 목표, 학생 활동, 교사 지원, 산출물, 평가 증거
- Act의 대상·맥락·실행물·판단 기준·안전·중단 조건·대체안
- AI 사용 또는 `AI 미사용`, 개인정보·보안 경계

사용 양식은 [`../02-TRACES-수업안-확정/확정-수업안-템플릿.md`](../02-TRACES-수업안-확정/확정-수업안-템플릿.md)이다.

## 2. `content.py`를 작성한다

과거 엔진은 아래 두 변수를 입력으로 읽는다.

```python
COMMON = {
    # 6차시 전체에 공통인 기본 정보와 설계 내용
}

CHASI = {
    1: {},  # Trigger
    2: {},  # Research
    3: {},  # Architect
    4: {},  # Change-plan
    5: {},  # Execute
    6: {},  # Study
}
```

이 예시는 **Python 문법을 보여 주는 빈 뼈대일 뿐**이다. 실제 엔진이 요구하는 차시별 키와 자료형은 과거 작동한 `content.py`를 기준으로 작성한다. 최소한 차시마다 `rubric`, `feedback`, `saenggibu`, `performance`, `lesson`이 필요하며, `lesson`에는 `std`, `date`, `place`, `teacher`, `unit_chasi`, `topic`, `objective`, `competency`, `materials`, `stages`를 넣는다. `stages`는 단계명, 활동 목록, 자료·유의점 목록의 묶음이다.

### `COMMON`에 넣는 내용

- `file_prefix`: 최종 파일명 접두사
- 교사·학교·학년·과목·단원
- 성취기준 목록
- 문제 상황, Challenge, Essential Question
- 핵심역량, 공통 자료, Big Idea, AI 활용 원칙
- `chasi_table`: TRACES 1~6차시 전체 흐름
- 산출물과 참고문헌

### 각 `CHASI[n]`에 넣는 내용

- 해당 차시의 평가 기준·피드백·개인 학습 기록 문장
- 수행 과제의 문제·Challenge·탐구·산출물·발표·역할
- `lesson`: 일시, 장소, 교사, 단원·차시, 주제, 목표, 역량, 자료, 도입·활동·정리 단계

### 작성 규칙

- 확정 Markdown에 없는 문장이나 수치를 생성용 코드에 임의로 추가하지 않는다.
- `CHASI[1]`~`CHASI[6]`은 각각 T, R, A, C, E, S와 정확히 대응한다.
- 5차시 Execute는 발표만이 아니라 제한 실행 또는 명시적 모의 적용의 기록을 포함한다.
- 6차시 Study에는 판단 기준 대비 결과, 수정·유지 이유, 한계, 개인 성찰을 포함한다.
- 활동지·예시 결과지는 수업자료 목록과 생성 요청서에 파일명·버전·삽입 위치를 적는다.

작성 뒤에는 Python 문법을 먼저 확인한다.

```bash
python3 -m py_compile /별도작업/content.py
```

## 3. 템플릿으로 HWPX 초안을 생성한다

생성 전 원본 템플릿은 보존하고 작업용 복사본만 사용한다.

```bash
# 1차시만 시험 생성
python3 /승인된-생성도구/build_engine.py \
  /별도작업/content.py \
  /별도작업/form_template_복사본.hwpx \
  /별도작업/output 1

# 3) 1~6차시 통합 HWPX를 생성한다. 이 명령은 활동지·예시의 파일명·버전·삽입 위치가 생성 요청서에 확정된 뒤에만 실행한다.
python3 /승인된-생성도구/build_engine.py \
  /별도작업/content.py \
  /별도작업/form_template_복사본.hwpx \
  /별도작업/output 1 2 3 4 5 6
```

- `--separate`를 붙이면 차시별 파일을 각각 생성한다. 기본은 통합 HWPX다.
- 1차시 시험본을 실제 한글에서 열어 템플릿 표, 글꼴, 단원 1~4, 수식 영역, 쪽 구성이 유지되는지 확인한 뒤 통합본을 만든다.
- 템플릿의 표 구조·셀 주소·수식 영역을 바꾸지 않는다.
- HWPX 압축을 풀어 XML을 문자열 치환하는 방식은 사용하지 않는다.

## 4. 활동지·예시 결과지를 만든 뒤 최종 HWPX를 생성한다

앞의 1차시 시험 생성은 템플릿과 엔진이 현재 양식에서 작동하는지 보는 **호환성 시험**이다. 제출용 6차시 통합본을 먼저 확정하는 단계가 아니다. 부속자료 승인 목록에 따라 학생 활동지와 교사용 예시를 만든 뒤, 그 파일명·버전·삽입 위치를 포함해 최종 통합 HWPX를 생성·편집한다.

1. [`../03-활동지와-예시결과지/활동지-웹제작-안내.md`](../03-활동지와-예시결과지/활동지-웹제작-안내.md)에 따라 A4 HTML 활동지를 만든다.
2. 학생용은 학생의 판단·계산·근거를 쓸 빈칸을 남기고 답을 선공개하지 않는다.
3. 교사용 예시는 안전한 가상 자료, 계산, 가정, 한계를 표시하고 학생용과 구분한다.
4. HTML을 PDF와 필요 시 PNG로 내보낸다.
5. PDF를 열어 글자 크기, 표 잘림, 그래프·수식 겹침, 흑백 인쇄 가독성을 사람이 확인한다.
6. 이 파일의 이름·버전·삽입 위치를 생성 요청서에 적은 뒤 1~6차시 통합 HWPX를 생성하고, 한글에서 수작업으로 삽입·조판한다.

## 5. 사람이 HWPX를 마무리한다

이 단계는 자동화를 건너뛸 수 없다. HWPX 편집 담당자는 한글 프로그램에서 생성된 통합 HWPX를 열고 다음을 수작업으로 한다.

- 학생용 활동지와 교사용 예시 결과지를 지정한 차시·부록 위치에 삽입
- 이미지/PDF의 크기, 여백, 줄바꿈, 쪽 나눔 조정
- 활동지 제목·학생용/교사용 구분·차시 번호의 일치 확인
- 표가 쪽 밖으로 나가지 않는지, 수식·그림·글자가 겹치지 않는지 확인
- 자동 생성으로 채워지지 않는 템플릿 고유 영역을 승인된 내용으로 보완
- 최종 파일의 버전을 올리고 생성·수정 이력을 기록

사람 수작업은 자동 생성의 실패를 감추는 일이 아니라, 실제 학교 양식과 인쇄·배포 조건을 만족시키는 필수 품질 단계다.

## 6. 최종 검증과 제출

1. `unzip -t 최종파일.hwpx`로 패키지 무결성을 확인한다.
2. `kordoc 최종파일.hwpx -o 역추출.md --silent`으로 내용 역추출을 수행한다.
3. 확정 Markdown과 제목·성취기준·TRACES 6차시·산출물·안전 경계를 대조한다.
4. 최종 HWPX를 PDF 또는 쪽별 이미지로 내보내 실제 조판을 사람이 확인한다.
5. [`../05-HWPX검증과-제출기록/HWPX-검증-보고서.md`](../05-HWPX검증과-제출기록/HWPX-검증-보고서.md)에 결과·차이·재생성·최종 판정을 기록한다.

검증 결과가 `배포 가능`일 때만 제출용 HWPX를 공유한다.
