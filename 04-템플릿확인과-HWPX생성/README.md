# 4단계: 템플릿 확인과 HWPX 생성

## 목적

확정된 TRACES 6차시 수업안과 활동지·예시 결과지를 동아리의 **기존 CBL HWPX 템플릿**에 채워 제출용 HWPX로 만든다.

이 단계는 새 HWPX를 임의로 조립하는 단계가 아니다. 이전 `club-plan` 저장소에서 사용한 `cbl-lesson-maker`의 `form_template.hwpx`와 `build_engine.py` 방식처럼, **승인된 템플릿의 표 구조와 셀 주소를 유지한 채 확정 콘텐츠를 넣는 방식**을 우선한다.

## 이전 작업에서 실제로 확인한 생성 자산

이전 `club-plan` 저장소의 보존 커밋 `3e088cdf`에는 다음 자산이 있었다.

| 자산 | 역할 | 확인한 사실 |
|---|---|---|
| `.opencode/skills/cbl-lesson-maker/assets/form_template.hwpx` | CBL 수업 설계 양식 | ZIP 무결성 검사 통과. 단원 1·2 공통, 단원 3·4 차시별 표를 가진 양식 |
| `.opencode/skills/cbl-lesson-maker/scripts/build_engine.py` | 양식 채우기 생성 엔진 | `content.py`, 템플릿 HWPX, 출력 폴더, 차시 번호를 입력받아 HWPX 생성 |
| `교사별-산출물/*/content.py` | 생성 입력 데이터 | `COMMON`(공통 정보)과 `CHASI`(차시별 정보) 구조로 수업 내용을 분리 |

이 엔진의 실제 호출 형식은 다음이었다.

```bash
python build_engine.py <content.py> <form_template.hwpx> <out_dir> [차시번호...] [--separate]
```

- 차시 번호를 여러 개 주면 기본으로 `첫차시-마지막차시_통합.hwpx`를 만든다.
- `--separate`를 붙일 때만 차시별 HWPX를 각각 만든다.
- 엔진은 템플릿의 표와 셀 주소를 기준으로 공통 정보와 차시별 내용을 넣고, 생성 뒤 ZIP 무결성을 검사한다.
- 이 엔진·템플릿은 이 최종 제출 저장소에 복사하지 않는다. 실제 생성은 승인된 별도 작업 위치에서 수행한다.

## 입력과 기록 위치

- 확정 수업안: [`../02-TRACES-수업안-확정/`](../02-TRACES-수업안-확정/)
- 활동지·예시 결과지: [`../03-활동지와-예시결과지/`](../03-활동지와-예시결과지/)의 별도 작업 폴더 산출물
- 생성 요청서: [`HWPX-생성-요청서.md`](HWPX-생성-요청서.md)
- 제출용 HWPX, 템플릿 HWPX, `content.py`, 생성 엔진, HTML·PDF·PNG는 이 저장소 밖 생성 작업 폴더에 둔다.

## 4-1. 템플릿 HWPX를 먼저 확인한다

생성 전에는 최신 승인 템플릿을 실제로 확인한다. 이전 양식의 셀 주소를 새 양식에 그대로 가정하지 않는다.

1. 템플릿 파일명, 버전, 제공자, 보관 위치, 적용 대상 차시를 생성 요청서에 기록한다.
2. 템플릿 원본은 읽기 전용으로 보관하고 작업용 복사본을 만든다.
3. 작업용 복사본을 한글 프로그램으로 열어 단원 1~4, 표·병합 셀·수식 영역·머리말·쪽 구성을 확인한다.
4. `unzip -t 템플릿.hwpx`로 HWPX 패키지 무결성을 확인한다.
5. `kordoc 템플릿.hwpx -o 템플릿-역추출.md --silent`으로 역추출본을 만들고 제목, 필수 표, 차시별 입력 영역을 표시한다.
6. 엔진을 쓰기 전에는 복사본과 최소한의 시험용 `content.py`로 **1개 차시 시험 생성**을 한다. 결과 HWPX를 열고 템플릿 표·글꼴·수식 영역이 유지되는지 확인한다.

## 4-2. `content.py`를 작성하는 법

기존 생성 엔진은 다음 두 덩어리의 데이터를 요구한다.

- `COMMON`: 교사·학교·학년·과목·단원·성취기준·Big Idea·Essential Question·Challenge·핵심역량·자료·AI 활용·전체 차시표·산출물·참고문헌처럼 모든 차시에 공통인 내용
- `CHASI`: 차시별 평가 기준, 피드백, 개인 기록 예시, 수행 과제, 과정안(일시·장소·차시·주제·목표·역량·자료·수업 단계)

작성 순서:

1. 확정 Markdown의 내용을 `COMMON`과 `CHASI[1]`~`CHASI[6]`으로 옮긴다.
2. `COMMON['chasi_table']`에는 TRACES 6차시 전체를, 각 `CHASI[n]['lesson']`에는 해당 차시의 구체적 활동을 넣는다.
3. 수업안 Markdown에 없는 수치·성취기준·활동·평가 문구를 새로 추가하지 않는다.
4. 학생 활동지·교사용 예시 PDF·PNG의 파일명과 삽입 위치를 `materials` 또는 생성 기록에 명확히 적는다.
5. Python 문법을 확인한 뒤 1개 차시를 먼저 생성한다.

기존 2차시 `content.py` 구조를 6차시로 확장하는 것이며, 과거 2차시·10차시 자료를 그대로 제출용 내용으로 전용하는 것이 아니다. 현재 최종 제출의 기준은 TRACES 6차시 확정 Markdown이다.

## 4-3. 생성 순서

```bash
# 1) 확정 수업안에 맞춘 입력 데이터의 문법을 확인한다.
python3 -m py_compile /별도작업/content.py

# 2) 템플릿 복사본으로 1차시 시험 생성한다.
python3 /승인된-생성도구/build_engine.py \
  /별도작업/content.py \
  /별도작업/템플릿-복사본.hwpx \
  /별도작업/output 1

# 3) 1~6차시 통합 제출용 HWPX를 생성한다.
python3 /승인된-생성도구/build_engine.py \
  /별도작업/content.py \
  /별도작업/템플릿-복사본.hwpx \
  /별도작업/output 1 2 3 4 5 6
```

- 1차시 시험본을 열고 문제가 없을 때만 통합본을 만든다.
- 차시별 개별 파일이 필요할 때만 마지막에 `--separate`를 붙인다.
- 템플릿의 ZIP/XML을 직접 문자열 치환하지 않는다. 기존 엔진은 XML 라이브러리로 템플릿 복사본의 셀을 채우도록 작성돼 있다.
- 엔진이 지원하지 않는 표 병합, 수식, 그림 배치가 있으면 먼저 한글 프로그램에서 템플릿 복사본으로 처리 가능한지 시험하고, 결과를 검증한다.

## 4-4. 활동지와 예시 결과지를 넣는다

- 학생용 활동지와 교사용 예시 결과지는 파일명·버전·삽입 쪽을 생성 요청서에 기록한다.
- HWPX 양식에 이미 자료 첨부 영역이 있다면 그 위치를 사용한다. 새 표 구조를 임의로 만들지 않는다.
- HTML에서 만든 PDF·PNG는 먼저 별도 작업 폴더에서 열어 인쇄 품질을 확인한다.
- 삽입 뒤 HWPX를 열어 이미지 해상도, 위치, 쪽 나눔, 학생용/교사용 구분을 확인한다.
