# 4단계: 템플릿 확인과 HWPX 생성

## 목적

확정 Markdown, 활동지 PDF·PNG, 승인된 HWPX 템플릿을 사용해 제출용 HWPX를 만든다. 템플릿을 먼저 파악하고, 구조를 보존한 채 내용만 채운다.

## 입력과 기록

- 확정 수업안: `../02-TRACES-수업안-확정/`에서 완성한 Markdown
- 활동지·예시 결과지: `../03-활동지와-예시결과지/`의 별도 작업 폴더 산출물
- 생성 요청서: [`../templates/HWPX-생성-요청서.md`](../templates/HWPX-생성-요청서.md)
- 최종 HWPX·템플릿 HWPX·중간 파일은 이 저장소 밖 작업 폴더에 둔다.

## 4-1. 템플릿 HWPX를 먼저 확인한다

HWPX 템플릿을 받아 다음을 확인한다.

1. 템플릿 파일명, 버전, 제공자, 사용 목적을 생성 요청서에 기록한다.
2. 템플릿을 실제 한글 프로그램 또는 승인된 문서 도구로 열어 표·병합 셀·수식 영역·머리말·쪽 구성을 확인한다.
3. `kordoc 템플릿.hwpx -o 템플릿-역추출.md --silent`으로 Markdown 역추출본을 만들고, 제목·표·필수 항목이 무엇인지 표시한다.
4. 템플릿에 누름틀·입력 필드가 있다면 `kordoc fill 템플릿.hwpx --dry-run`으로 인식되는 필드 목록을 확인하고, 실제 복사본에서 `kordoc fill`로 채우기 결과를 시험한다.
5. 원본 템플릿은 수정하지 않는다. 생성은 복사본에서만 수행한다.

## 4-2. 어떤 생성 방법을 쓸지 정한다

### A. 템플릿의 입력칸을 채우는 방법: 우선 사용

승인된 HWPX 템플릿에 문구·표·입력칸이 준비돼 있으면 이 방법을 우선 사용한다.

- 템플릿 구조를 바꾸지 않고 확정 Markdown의 값만 채운다.
- `kordoc fill`은 HWPX의 라벨-값 쌍을 채우는 용도로 사용할 수 있다. 실행 전 템플릿 복사본에서 결과를 열어 서식·표가 보존되는지 확인한다.
- `kordoc patch`는 원본 HWPX와 사람이 검토한 편집 Markdown을 비교해 서식을 유지하며 반영하는 방식이다. 반드시 원본의 복사본을 출력 대상으로 쓴다.
- 자동 채우기로 처리할 수 없는 복잡한 표·수식·이미지 위치는 승인된 양식 도구로 작성한다. ZIP/XML 문자열 치환은 사용하지 않는다.

### B. Markdown에서 새 HWPX를 만드는 방법: 템플릿이 없을 때만 사용

`kordoc`에는 Markdown 헤딩·문단·목록·표 등을 HWPX로 만드는 기능이 있다. 그러나 이 방식은 기존 학교 양식의 복잡한 표·수식·병합·디자인을 그대로 재현한다고 가정하면 안 된다.

- 제출 양식이 정해져 있다면 A 방식을 쓴다.
- 단순한 보조 문서·활동지 부록처럼 표와 문단 중심인 문서에만 새 HWPX 생성을 검토한다.
- 생성 결과는 반드시 실제 열기, ZIP 무결성, 역추출, 렌더링 검수를 통과해야 한다.

## 4-3. 생성 요청서에 반드시 적을 것

- 확정 수업안 Markdown 경로와 확인자·일자
- 생성 대상: 수업지도안, 학생 활동지, 교사용 예시, 평가 기록지 등
- 생성 차시와 최종 HWPX 파일명·버전
- 템플릿 파일명·버전·저장 위치
- 생성 도구·버전과 생성 담당자
- 활동지 PDF·PNG의 파일명, 학생용/교사용 구분, HWPX 삽입 위치
- 생성 작업 폴더와 검증 담당자에게 넘길 SHA-256 기록 위치

## 완료 기준

- [ ] 확정 Markdown과 생성 요청서가 함께 있다.
- [ ] 템플릿 HWPX를 실제로 열고 역추출해 구조를 확인했다.
- [ ] 원본 템플릿이 아니라 복사본으로 생성했다.
- [ ] 표 구조·병합·수식 영역·머리말·쪽 구성을 임의로 바꾸지 않았다.
- [ ] 학생용 활동지와 교사용 예시의 삽입 위치·버전이 확인됐다.
- [ ] 생성 파일은 별도 작업 폴더에만 있다.
